Factory Design Pattern
****************************************************************
====================================

/**
 * Imagine you're designing a Notification system.
 *
 * Requirement:
 * Send notifications through different channels:
 * 1. Email
 * 2. SMS
 * 3. Push Notification
 */

public class EmailNotification {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}

public class SmsNotification {
    public void send(String message) {
        System.out.println("SMS: " + message);
    }
}

public class PushNotification {
    public void send(String message) {
        System.out.println("Push: " + message);
    }
}

Option 1: 
    Direct Object Creation
    EmailNotification notification = new EmailNotification();
    notification.send("Order Delivered");

Later:
    SmsNotification notification =  new SmsNotification();
    notification.send("OTP: 1234");

Later:
    PushNotification notification =  new PushNotification();
    notification.send("New Message");

Problems
/**
 * Every client must know:
 *
 * 1. Which class to instantiate
 * 2. How to create it
 * 3. When new notification types are added,
 *    client code must change.
 */

 Example:
 ------------------
 if(type.equals("EMAIL")) {
    notification = new EmailNotification();
} else if(type.equals("SMS")) {
    notification = new SmsNotification();
} else if(type.equals("PUSH")) {
    notification = new PushNotification();
}

Problem with this approch 
/**
 * 1. Tight coupling.
 * 2. Every caller contains object creation logic.
 * 3. Difficult to extend.
 * 4. Violates Open Closed Principle.
 */

 Factory Solution
 ********************************
 Step 1: Common Interface
    public interface Notification {
        void send(String message);
    }

Step 2: Concrete Implementations

    public class EmailNotification implements Notification {
        @Override
        public void send(String message) {
            System.out.println("Email: " + message);
        }
    }

    public class SmsNotification implements Notification {
        @Override
        public void send(String message) {
            System.out.println("SMS: " + message);
        }
    }

    public class PushNotification implements Notification {
        @Override
        public void send(String message) {
            System.out.println("PUSH: " + message);
        }
    }


Advantages

/**
 * 1. Hides object creation.
 * 2. Reduces coupling.
 * 3. Easier to extend.
 * 4. Client depends on interface.
 * 5. Centralized creation logic.
 */

 Thumb Rules: When Should You Use Factory?
 ----------------------------------------------
 /**
 * Use Factory when:
 *
 * 1. Object creation is complex.
 *
 * 2. Multiple implementations exist.
 *
 * 3. Client should not know
 *    concrete classes.
 *
 * 4. Creation logic is repeated
 *    across the application.
 *
 * 5. Future implementations
 *    may be added.
 */
